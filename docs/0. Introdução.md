# Helper: Ecossistema Móvel para Execução de Micro Aplicativos Web

## Introdução

No cenário atual do desenvolvimento móvel, o modelo tradicional de distribuição de softwares baseia-se no download e na instalação de aplicativos nativos individuais via lojas de aplicações. Embora esse formato ofereça alto desempenho e integração com o sistema operacional, ele gera desafios crescentes de fragmentação, consumo excessivo de armazenamento e burocracia no ciclo de atualização. A necessidade de instalar um aplicativo dedicado para cada serviço secundário ou utilitário esporádico resulta em uma sobrecarga desnecessária no dispositivo do usuário.

O **Helper** surge como uma solução para esse problema, funcionando como uma plataforma móvel modular inspirada no conceito de _Superapps_. O sistema opera como um ambiente hospedeiro central (**Lobby**) desenvolvido em React Native, projetado para executar pequenos aplicativos utilitários chamados de **micro-apps** (ou módulos). A plataforma conecta-se a um mercado de módulos (**Marketplace**) remoto, baixa os micro-apps sob demanda em arquivos compactados (`.zip`), extrai os ativos estáticos e os executa localmente de forma totalmente _offline_.

O principal diferencial do projeto é a **democratização do desenvolvimento**: os módulos são construídos inteiramente com tecnologias web padrões (HTML5, CSS3, JavaScript ES6+) ou frameworks modernos (React, Vue, Vite), sendo executados dentro de contêineres web isolados e seguros (`react-native-webview`). Para superar as limitações tradicionais das _WebViews_ quanto ao acesso ao hardware, o Helper implementa um barramento customizado de comunicação assíncrona bidirecional via JSON (**Bridges**), permitindo que o código web consuma recursos nativos do dispositivo — como Câmera, GPS, Sensores de Movimento e Armazenamento Persistente — de maneira transparente e segura.

## Visão Geral do Fluxo de Funcionamento

```
┌─────────────────┐      HTTP / ZIP       ┌─────────────────┐
│   Marketplace   │ ────────────────────> │  App Hospedeiro │
│    (Backend)    │                       │  (React Native) │
└─────────────────┘                       └────────┬────────┘
                                                   │
                                            Instancia e Controla
                                                   │
                                                   ▼
┌─────────────────┐     postMessage       ┌─────────────────┐
│ Bridge Nativa   │ <───────────────────> │     WebView     │
│ (Acesso ao H/W) │    Mensageria JSON    │   (Micro-App)   │
└─────────────────┘                       └─────────────────┘

```

1. **Descoberta:** O Helper consulta o catálogo `apps.json` do Marketplace remoto para listar os módulos disponíveis para download.
2. **Instalação e Cache Local:** Ao selecionar um módulo, o Helper faz o download do pacote contendo os ativos estáticos (`index.html`, scripts e estilos) e os armazena na memória privada do dispositivo.
3. **Execução Isolada:** O módulo é renderizado na `WebViewScreen`, isolado do restante do sistema operacional e de outros micro-apps.
4. **Comunicação Híbrida (Bridges):** Quando o micro-app necessita de recursos nativos do dispositivo, ele envia mensagens assíncronas via barramento de eventos (`handleBridgeMessage`) para o núcleo nativo, que valida o escopo e as permissões antes de executar a operação solicitada.

## Objetivos do Projeto

- **Modularidade:** Permitir a adição, remoção e atualização de micro-apps dinamicamente, sem exigir o envio de uma nova versão do aplicativo nativo às lojas.
- **Segurança e Isolamento (Sandboxing):** Garantir a separação estrita de dados e recursos entre diferentes micro-apps, impedindo o acesso não autorizado a arquivos ou partições de armazenamento de terceiros.
- **Desempenho e Acesso a Hardware:** Fornecer um barramento de comunicação bidirecional de baixa latência para permitir que código Web execute tarefas avançadas de telemetria, captura de mídia e processamento local.
- **Portabilidade:** Manter a interface dos micro-apps agnóstica de bibliotecas do Helper, garantindo que qualquer aplicação web padrão possa ser adaptada ao ecossistema com alterações mínimas.
