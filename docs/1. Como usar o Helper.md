## Guia de Uso do Helper

### Definições e Conceitos Fundamentais

Para compreender o funcionamento e a navegação no ecossistema Helper, é necessário formalizar a definição dos dois pilares de sua arquitetura de distribuição:

- **Módulo (Micro-App):** Qualquer aplicação web projetada para rodar dentro do contêiner do Helper. Sob a perspectiva do usuário final, é uma funcionalidade ou utilitário importado através do Marketplace. Sob a perspectiva do desenvolvedor, é uma aplicação web (construída com HTML, CSS e JavaScript puro ou frameworks como React e Vite) adaptada para interagir com o hardware do celular por meio das _Bridges_ nativas da plataforma.
- **Marketplace:** O servidor distribuidor central de módulos. Funciona como um catálogo remoto que disponibiliza pacotes compactados (`.zip`) contendo todo o código-fonte estático dos micro-apps para download e execução local offline.

---

### Configuração Inicial Obrigatória

Antes de realizar a navegação e o download de módulos, é necessário vincular o aplicativo hospedeiro a um servidor de distribuição ativo:

1. Na tela principal (**Home**), toque no **ícone de engrenagem** localizado na barra superior para acessar a tela de **Configurações**.
2. No campo de endereço do servidor, informe a **URL completa do Marketplace** desejado (ex: `[http://192.168.1.100:5000](http://192.168.1.100:5000)` para execução em rede local ou o domínio público do servidor).
3. Salve as alterações. Essa configuração é fundamental para que o Helper consiga consultar o endpoint `apps.json` e sincronizar o catálogo de micro-apps disponíveis.

---

### Modelo de Gestão de Permissões e Segurança

Diferente de sistemas operacionais tradicionais que exibem alertas pop-up no momento em que um recurso é solicitado, o Helper adota um modelo de **gerenciamento explícito e prévio de permissões**:

1. **Atribuição Manual de Permissões:** O aplicativo nativo **não solicita permissões automaticamente em tempo de execução**. Para que um módulo possa acessar capacidades de hardware (como Câmera, GPS, Microfone ou Armazenamento), o usuário deve acionar as **Configurações do Módulo** no Home e conceder explicitamente o acesso a cada recurso desejado.
2. **Monitoramento e Alertas em Tempo de Execução:** Durante a utilização de um micro-app, se o módulo tentar acionar uma _Bridge_ para a qual não recebeu autorização prévia, a execução daquela chamada nativa é bloqueada. O Helper exibirá um aviso (ex: via `ToastAndroid`) informando ao usuário que o módulo tentou utilizar um recurso não permitido.
3. **Revogação a Qualquer Momento:** O consentimento concedido não é definitivo. O usuário possui total autonomia para retornar às configurações individuais do módulo no Home e **revogar o acesso a qualquer recurso** instantaneamente.

### Compatibilidade e Padrões de Roteamento de URLs

Como o Helper renderiza as aplicações através de um contêiner `WebView`, **sites e aplicações web convencionais tendem a ser nativamente compatíveis com a plataforma**. No entanto, existem requisitos específicos de estruturação de rotas e URLs para garantir a execução correta:

#### 1. Incompatibilidade com Resolução Implícita de Rotas

Aplicações web modernas desenvolvidas com roteamento no lado do cliente (Single Page Applications - SPAs com React Router, Vue Router, etc.) frequentemente dependem da reescrita de URLs pelo servidor.

Se um módulo for configurado para iniciar em uma rota relativa específica (como `[meusite.com/telaInicial](https://meusite.com/telaInicial)`), ele poderá apresentará falhas de carregamento ou tela em branco no Helper se a URL de entrada fornecida for apenas a raiz (`meusite.com`).

#### 2. Requisitos de Estruturação para Módulos

Para garantir compatibilidade total com o modelo de download e execução local (offline-first) do Helper, a aplicação web deve seguir as diretrizes:

- **Ponto de Entrada Fixo (`index.html`):** O módulo deve obrigatoriamente possuir um arquivo `index.html` na raiz do seu pacote para servir de ponto de inicialização estático.
- **Caminhos Relativos para Assets:** Todos os links de scripts, folhas de estilo e imagens devem utilizar caminhos relativos (`./script.js` em vez de `/script.js`).
- **Roteamento Hash (HashRouter):** Caso o módulo utilize um framework com roteamento interno, deve-se priorizar o modo baseado em Hash (`/#/telaInicial`), garantindo que a navegação ocorra sem dependência do protocolo de rotas do servidor web.

### Passos para Utilizar o Helper

#### 1. Acessando o Home

Ao abrir o aplicativo hospedeiro, o usuário é apresentado ao **Home**, a tela principal que exibe a lista de módulos já instalados localmente no dispositivo e os controles de configuração.

#### 2. Baixando Módulos do Marketplace

1. Certifique-se de que a URL do Marketplace foi previamente definida nas Configurações Gerais.
2. Dentro do Home, toque no ícone do **Marketplace**.
3. O Helper fará uma requisição HTTP para o servidor configurado e listará os módulos disponíveis no catálogo.
4. Ao selecionar um módulo, o aplicativo baixa o pacote `.zip`, descompacta o conteúdo no armazenamento privado do dispositivo e salva as informações de cache.
5. O ícone do módulo passa a ser exibido no Home do usuário.

#### 3. Configurando Permissões e Executando um Módulo

1. Antes ou após iniciar um módulo recém-instalado, acesse o menu de **Configurações do Módulo** no Home.
2. Ative as permissões específicas que deseja autorizar para aquele micro-app (Câmera, Localização, etc.).
3. Toque no card do módulo para abri-lo na `WebViewScreen`.
4. Caso o módulo tente acionar uma funcionalidade cujo acesso não foi previamente concedido nas configurações, a ação será bloqueada e um aviso informativo será exibido na tela.
