## 2.1 StorageBridge (`storage`)

A `StorageBridge` gerencia a persistência de dados local chave-valor no dispositivo utilizando o `AsyncStorage` do React Native. Ela provê isolamento de dados por escopo (**Sandboxing**), garantindo que cada micro-app acesse exclusivamente seus próprios registros sem interferir ou visualizar informações de outros módulos instalados no Helper.

---

### Mecanismo de Isolamento e Segurança

Todas as chaves recebidas passam por um processo de sanitização e prefixação baseado no `appId` do módulo fornecido no contexto:

1. **Sanitização de Entrada:** O `appId` e a `key` são filtrados via Regex (`/[^a-zA-Z0-9_-]/g`), removendo caracteres especiais e prevenindo ataques de injeção de delimitadores ou navegação de diretório.
2. **Escopo de Chaves:** As chaves salvas no `AsyncStorage` nativo seguem o padrão `@app_<safeAppId>:<safeKey>`.
3. **Barreira de Contexto:** Caso uma requisição seja feita sem um `appId` válido no contexto, a operação é abortada antes de interagir com o banco de dados.

---

### Ações Disponíveis (`actions`)

---

#### 1. `STORAGE_SAVE`

Armazena ou atualiza um valor associado a uma chave no armazenamento privado do micro-app.

- **O que faz:** Converte o valor recebido em JSON string e o persiste no `AsyncStorage` com o prefixo do `appId`.
- **Parâmetros Esperados (`params`):**
- `key` _(String, Obrigatório)_: Nome da chave.
- `value` _(Any, Obrigatório)_: Dado a ser armazenado (String, Number, Object, Array, Boolean).

```json
// Envio
{
  "module": "storage",
  "action": "STORAGE_SAVE",
  "params": {
    "key": "user_preferences",
    "value": { "theme": "dark", "fontSize": 14 }
  },
  "callbackId": "req_save_01"
}
```

- **Retorno em Caso de Sucesso (`sendToWebView`):**

```json
{
  "callbackId": "req_save_01",
  "module": "storage",
  "type": "SAVE_SUCCESS",
  "success": true,
  "key": "user_preferences"
}
```

---

#### 2. `STORAGE_GET`

Recupera o valor armazenado associado a uma chave específica do micro-app.

- **O que faz:** Busca a chave prefixada do módulo. Se o valor for uma string JSON válida, realiza o parse automaticamente e devolve o dado estruturado; caso contrário, retorna a string bruta.
- **Parâmetros Esperados (`params`):**
- `key` _(String, Obrigatório)_: Nome da chave a ser consultada.

```json
// Envio
{
  "module": "storage",
  "action": "STORAGE_GET",
  "params": {
    "key": "user_preferences"
  },
  "callbackId": "req_get_01"
}
```

- **Retorno em Caso de Sucesso (`sendToWebView`):**

```json
{
  "callbackId": "req_get_01",
  "module": "storage",
  "type": "STORAGE_DATA",
  "success": true,
  "key": "user_preferences",
  "value": { "theme": "dark", "fontSize": 14 }
}
```

_(Nota: Se a chave não existir, o campo `value` retornará `null`)._

---

#### 3. `STORAGE_REMOVE`

Remove um registro específico do armazenamento privado do micro-app.

- **O que faz:** Deleta a chave identificada pelo escopo `@app_<appId>:<key>`.
- **Parâmetros Esperados (`params`):**
- `key` _(String, Obrigatório)_: Nome da chave a ser removida.

```json
// Envio
{
  "module": "storage",
  "action": "STORAGE_REMOVE",
  "params": {
    "key": "user_preferences"
  },
  "callbackId": "req_rem_01"
}
```

- **Retorno em Caso de Sucesso (`sendToWebView`):**

```json
{
  "callbackId": "req_rem_01",
  "module": "storage",
  "type": "REMOVE_SUCCESS",
  "success": true,
  "key": "user_preferences"
}
```

---

#### 4. `STORAGE_CLEAR`

Limpa **todos** os dados armazenados exclusivamente pelo micro-app atual.

- **O que faz:** Consulta todas as chaves cadastradas no `AsyncStorage`, filtra apenas as que iniciam com o prefixo `@app_<appId>:` do módulo em execução e as remove em lote (`multiRemove`). Dados de outros micro-apps não são afetados.
- **Parâmetros Esperados (`params`):** Nenhum (objeto vazio `{}`).

```json
// Envio
{
  "module": "storage",
  "action": "STORAGE_CLEAR",
  "params": {},
  "callbackId": "req_clr_01"
}
```

- **Retorno em Caso de Sucesso (`sendToWebView`):**

```json
{
  "callbackId": "req_clr_01",
  "module": "storage",
  "type": "CLEAR_SUCCESS",
  "success": true
}
```

---

### Estrutura de Retorno em Caso de Erro

Se ocorrer qualquer falha durante a execução (ausência de parâmetros obrigatórios, chave sem `appId` ou erro de E/S no dispositivo), o retorno segue o padrão:

```json
{
  "callbackId": "req_01",
  "module": "storage",
  "type": "ERROR",
  "success": false,
  "error": "O parâmetro \"key\" é obrigatório."
}
```
