## 2.4 SensorBridge (`sensors`)

A `SensorBridge` conecta os micro-apps à telemetria inercial e de movimento do dispositivo utilizando a biblioteca `react-native-sensors`. Ela provê dados contínuos de aceleração linear (**Acelerômetro**) e velocidade angular (**Giroscópio**) em frequências configuráveis, essenciais para aplicações de jogos, realidade aumentada e simulações físicas.

---

### Funcionamento Interno e Gerenciamento de Ciclo de Vida

1. **Assinaturas Reativas (RxJS Observables):** As leituras dos sensores operam no modelo de _publish/subscribe_. Cada sensor iniciado gera uma inscrição (`subscription`) ativa que transmite eventos continuamente para a WebView.
2. **Arredondamento e Normalização de Dados:** Para evitar estouro de memória e processamento excessivo de _garbage collection_ na conversão de ponta a ponta via JSON, os eixos $(x, y, z)$ são formatados em ponto flutuante com duas casas decimais (`parseFloat(val.toFixed(2))`).
3. **Limpeza e Economia de Bateria:** O componente mantém uma referência mutable (`subscriptions.current`) de todas as inscrições. Ao desmontar a tela ou ao trocar de micro-app, a rotina `stopAllSensors` executa o encerramento automático (`unsubscribe()`) de todos os sensores, evitando vazamento de memória (_memory leak_) e consumo fantasma de bateria.

---

### Ações Disponíveis (`actions`)

---

#### 1. `START_ACCELEROMETER`

Inicia a transmissão contínua de dados de aceleração linear e gravidade aplicada aos três eixos do dispositivo.

- **O que faz:** Cancela assinaturas anteriores do acelerômetro, ajusta o intervalo de amostragem no sistema operacional e passa a transmitir eventos do tipo `ACCELEROMETER_DATA`.
- **Parâmetros Esperados (`params`):**
- `interval` _(Number, Opcional)_: Intervalo de atualização em milissegundos. Padrão: `100` (10 Hz).

```json
// Envio
{
  "module": "sensors",
  "action": "START_ACCELEROMETER",
  "params": {
    "interval": 50
  },
  "callbackId": "acc_start_01"
}
```

- **Retorno Contínuo de Dados (`sendToWebView` - Evento Recorrente):**

```json
{
  "callbackId": "acc_start_01",
  "module": "sensors",
  "type": "ACCELEROMETER_DATA",
  "success": true,
  "data": {
    "x": 0.12,
    "y": 9.81,
    "z": 0.05,
    "timestamp": 1710000000000
  }
}
```

---

#### 2. `STOP_ACCELEROMETER`

Interrompe a leitura contínua e a transmissão de dados do acelerômetro.

- **O que faz:** Encerra a assinatura ativa do acelerômetro (`unsubscribe()`) e libera o recurso no hardware.
- **Parâmetros Esperados (`params`):** Nenhum (objeto vazio `{}`).

```json
// Envio
{
  "module": "sensors",
  "action": "STOP_ACCELEROMETER",
  "params": {},
  "callbackId": "acc_stop_01"
}
```

- **Retorno em Caso de Sucesso (`sendToWebView`):**

```json
{
  "callbackId": "acc_stop_01",
  "module": "sensors",
  "type": "SENSOR_STOPPED",
  "sensor": "accelerometer",
  "success": true
}
```

---

#### 3. `START_GYROSCOPE`

Inicia a transmissão contínua da velocidade de rotação do dispositivo ao redor dos eixos $x$, $y$ e $z$ (rad/s).

- **O que faz:** Cancela assinaturas prévias do giroscópio, configura a frequência de leitura e transmite eventos do tipo `GYROSCOPE_DATA`.
- **Parâmetros Esperados (`params`):**
- `interval` _(Number, Opcional)_: Intervalo de atualização em milissegundos. Padrão: `100` (10 Hz).

```json
// Envio
{
  "module": "sensors",
  "action": "START_GYROSCOPE",
  "params": {
    "interval": 100
  },
  "callbackId": "gyro_start_01"
}
```

- **Retorno Contínuo de Dados (`sendToWebView` - Evento Recorrente):**

```json
{
  "callbackId": "gyro_start_01",
  "module": "sensors",
  "type": "GYROSCOPE_DATA",
  "success": true,
  "data": {
    "x": 0.01,
    "y": -0.04,
    "z": 0.0,
    "timestamp": 1710000000000
  }
}
```

---

#### 4. `STOP_GYROSCOPE`

Interrompe a leitura contínua e a transmissão de dados do giroscópio.

- **O que faz:** Cancela a assinatura ativa do giroscópio (`unsubscribe()`) e desliga a amostragem de rotação.
- **Parâmetros Esperados (`params`):** Nenhum (objeto vazio `{}`).

```json
// Envio
{
  "module": "sensors",
  "action": "STOP_GYROSCOPE",
  "params": {},
  "callbackId": "gyro_stop_01"
}
```

- **Retorno em Caso de Sucesso (`sendToWebView`):**

```json
{
  "callbackId": "gyro_stop_01",
  "module": "sensors",
  "type": "SENSOR_STOPPED",
  "sensor": "gyroscope",
  "success": true
}
```

---

### Estrutura de Retorno em Caso de Erro

Caso o dispositivo físico não possua o sensor de hardware instalado (como o giroscópio em modelos de entrada) ou ocorra uma falha na amostragem, a ponte cancela a assinatura e devolve a seguinte mensagem:

```json
{
  "callbackId": "gyro_start_01",
  "module": "sensors",
  "type": "ERROR",
  "success": false,
  "error": "Giroscópio indisponível no dispositivo"
}
```
